# Система электронного архива

Консольное приложение для учёта электронных документов, пользователей
и выдачи документов из архива.

Проект развивается последовательно:

* **ПР1** — начальный сценарий проверки одного документа;
* **ПР2** — функциональная программа: коллекции, функции, модули,
  исключения, JSON-файлы, тесты;
* **ПР3** — предметная область переведена в объектную модель: классы,
  объекты, атрибуты, методы и взаимодействие объектов.

## Назначение

Приложение позволяет:

* просматривать список документов архива;
* добавлять новые документы;
* искать документы по названию;
* просматривать подробную информацию о документе;
* фильтровать документы по категории и по размеру;
* сортировать документы по названию;
* удалять документы;
* вести список пользователей архива;
* проверять доступность документа для выдачи;
* выдавать документы пользователям;
* закрывать выдачи при возврате документа;
* хранить данные между запусками приложения.

## Целевая аудитория

Сотрудники организации, которым необходимо вести учёт электронных
документов и контролировать, у кого из пользователей находится документ.

## Предметная область

Основными объектами предметной области являются:

* документ;
* пользователь;
* выдача документа.

Пользователь может получить документ из архива на определённую дату.
Один документ не может иметь двух активных выдач одновременно.
Закрытая выдача не блокирует документ и позволяет выдать его снова.

## Основные сущности

### `Document` — документ

Объект `Document` представляет электронный документ архива.

Основные атрибуты:

* `id` — уникальный идентификатор документа;
* `title` — название документа;
* `author` — автор документа;
* `category` — категория документа;
* `archive` — архив хранения;
* `size` — размер документа в КБ;
* `date` — дата добавления;
* `is_archived` — признак нахождения в архиве.

Основные методы:

* `matches()` — проверка совпадения названия с поисковым запросом;
* `is_in_category()` — проверка принадлежности категории;
* `is_larger_than()` — проверка размера документа;
* `move_to_archive()` — перевод документа в архив;
* `validate()` — статический метод проверки данных документа;
* `from_data()` — метод класса для создания документа из данных JSON;
* `to_data()` — подготовка данных документа для сохранения;
* `__str__()` — строковое представление документа.

### `User` — пользователь

Объект `User` представляет пользователя системы.

Основные атрибуты:

* `id` — уникальный идентификатор пользователя;
* `name` — имя пользователя;
* `email` — адрес электронной почты.

Основные методы:

* `matches()` — поиск по имени или адресу почты;
* `from_data()` — создание объекта `User` из набора данных;
* `to_data()` — подготовка данных пользователя для сохранения;
* `__str__()` — строковое представление пользователя.

### `Issue` — выдача документа

Объект `Issue` представляет выдачу документа пользователю.

Основные атрибуты:

* `id` — уникальный идентификатор выдачи;
* `document` — объект `Document`;
* `issue_date` — дата выдачи;
* `user` — объект `User`;
* `is_returned` — признак возврата документа.

Основные методы:

* `close()` — закрытие выдачи при возврате документа;
* `is_active()` — проверка того, что выдача не закрыта;
* `to_data()` — подготовка данных выдачи для сохранения;
* `__str__()` — строковое представление выдачи.

## Взаимодействие объектов

Объект `Issue` связывает документ и пользователя:

```text
User
 │ получает
Issue
 │ относится к
Document
```

Выдача хранит ссылки на объекты, а не только их идентификаторы,
поэтому данные связанных объектов доступны напрямую:

```python
issue.document.title
issue.document.size
issue.user.name
issue.user.email
```

Коллекции приложения содержат объекты предметной области:
`List[Document]`, `List[User]`, `List[Issue]`.

При создании выдачи проверяется отсутствие другой активной выдачи
этого же документа. При возврате объект `Issue` не удаляется из
коллекции: вызывается метод `close()`, после чего документ снова
доступен для выдачи.

## Хранение данных

Данные приложения хранятся в JSON-файлах:

* `data/documents.json`;
* `data/users.json`;
* `data/issues.json`.

При загрузке данные из JSON преобразуются в объекты `Document`, `User`
и `Issue`. При сохранении объекты преобразуются обратно в данные JSON.
Для связи выдачи с документом и пользователем в `issues.json`
используются идентификаторы `document_id` и `user_id`.

### Назначение модулей

* `main.py` — точка входа: меню приложения и пользовательские сценарии.
* `models/documents.py` — класс `Document` и функции работы
  с коллекцией документов.
* `models/users.py` — класс `User` и функции работы с пользователями.
* `models/issues.py` — класс `Issue` и функции работы с выдачами.
* `storage.py` — загрузка и сохранение данных: преобразование
  JSON в объекты Python и объектов Python в JSON.
* `utils.py` — безопасный ввод числа, даты и логического значения.
* `setup.cfg` — настройки `flake8` и `pytest`.
* `tests/` — автоматизированные тесты проекта.



## Тестирование

```bash
pytest -v
```

Тесты проверяют:

* создание и работу объектов `Document`, `User` и `Issue`;
* методы классов и строковые представления;
* операции с документами: добавление, поиск, фильтрацию,
  сортировку и удаление;
* создание и закрытие выдач;
* связь выдачи с документом и пользователем;
* правило доступности документа.
